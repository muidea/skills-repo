# Go 重构基准测试

只有性能是任务目标、现有 profile 指向热点，或结果需要声明性能改善时才编写基准。普通结构重构不强制增加 benchmark。

## 基线要求

- 固定 Go 版本、目标平台、输入规模和准备数据。
- 重构前后运行相同 benchmark，多次采样并保留原始输出。
- 优先使用目标仓库已经采用的 benchmark 风格；根据 `go.mod` 决定使用 `b.N` 或可用的新 API。
- 初始化放在计时区外，需要时使用 `b.ResetTimer()`、`b.StopTimer()` 和 `b.ReportAllocs()`。

## 比较指标

- 延迟或吞吐是否是用户真正关心的指标。
- `B/op` 与 `allocs/op` 是否改善，是否以更高 CPU、复杂度或内存峰值为代价。
- 结果是否超过噪声范围；可用时使用 `benchstat` 比较多次样本。
- 热点之外的可读性和维护成本是否明显退化。

没有稳定基线、profile 或统计上可信的差异时，不声明性能提升。
