# Go 项目布局与边界

Go 不存在必须套用的单一“标准项目布局”。重构时先识别目标仓库已经建立的运行单元、模块所有权和导入边界，不为了目录整齐搬迁代码。

## 判断顺序

1. 读取仓库的 `AGENTS.md`、README、结构文档和 `go.mod`。
2. 识别可执行入口、内部包、公开库、生成代码和基础设施适配器。
3. 通过调用关系和状态所有权判断代码落点，而不是只看文件名。
4. 只有目录位置造成循环依赖、错误公开面、重复所有权或维护障碍时才迁移。

## 常见目录的非强制语义

- `cmd/`：常用于可执行入口，但仓库可以采用其它明确约定。
- `internal/`：用于限制仓库外导入；不代表所有业务代码都必须迁入其中。
- `pkg/`：不是必需目录，只有确实需要对外复用的稳定包才应公开。
- `api/`、`scripts/`、`tools/`：是否使用取决于仓库现有组织方式。

目录迁移必须同步核对 import path、生成脚本、构建入口、文档和测试；如果迁移会改变公开 import path，它通常已超出纯内部重构边界。
